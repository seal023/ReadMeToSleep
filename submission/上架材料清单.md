### 4. 隐私政策 URL（ASC 必填）
- 已起草：`submission/隐私政策草案.md`。挂到任意静态托管（GitHub Pages / Vercel / 你自己的域名），把 URL 填进 ASC「App 隐私 → 隐私政策」。
- 记得把草案里的 `【开发者名称】` 替换为实际名称，联系邮箱可填 `seal023@163.com`。

### 5. 年龄分级 + 隐私营养标签
- 年龄分级：选 **4+**（面向 3–8 岁）。
- 若勾选「儿童类别（Made for Kids）」：Apple 对儿童类更严——**不得含任何第三方广告/统计/追踪 SDK**。请确认项目未集成 Firebase Analytics、广告 SDK 等（当前代码未见，提交前再核一遍 `package.json`）。
- 隐私营养标签（App 隐私问卷）建议勾选：
  - **Data Linked to You → User Content**：故事主题/细节、儿童录音会发到 AI 后端生成内容。
  - 其余（标识符、位置等）如未收集则选「未收集」。

### 6. 出口合规（已就绪 ✅）
- `app.json` 的 `ios.infoPlist.ITSAppUsesNonExemptEncryption: false` 已配置 → ASC 不会卡「缺少出口合规」。

### 7. 🟡 会员权益尚未做任何限制（潜在 2.3.1「描述与实际不符」）
- 现状：`services/iap.ts` 提供了 `isPremium()`，但**代码里没有任何地方调用它**。
  也就是说：免费用户实际也能用「无限故事 / 声音克隆 / 离线下载 / 自定义皮肤」——对比表上标着 ❌ 的功能，其实全都能用。
- 风险：Apple 审核员多半不会逐条验证免费额度，但一旦抽查到「付费才能用的功能免费也能用」，会按 **2.3.1 不实描述** 处理；且商业上等于白送会员。
- 建议（按优先级）：
  1. **最低成本**：把对比表改成「实际有什么就写什么」，去掉与实现不符的行（推荐先这样，不影响上架）。
  2. **完整方案**：在关键入口加门禁，例如每日生成次数、声音克隆入口、离线下载入口用 `isPremium()` 判断。
- 需要的话告诉我，我可以直接把门禁接上。
