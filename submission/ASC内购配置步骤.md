# App Store Connect 内购商品配置步骤

> 这一步**必须由你在 ASC 后台手动完成**（无 API 权限可代办）。代码侧已全部就绪，只要商品建好，App 就能拉到真实价格并完成购买。
>
> 代码里写死的商品 ID（**必须一字不差**）：
> - `com.seal023.ReadMeToSleep.monthly`
> - `com.seal023.ReadMeToSleep.yearly`

---

## 第 0 步：先完成两项协议（否则看不到内购菜单）

登录 https://appstoreconnect.apple.com → **业务（Business）** → **协议、税务和银行业务**：

1. 接受 **《付费应用协议》（Paid Apps Agreement）**
2. 填写 **联系人、银行、税务信息**（这三处状态都为「有效/已批准」才能提交内购审核）

> ⚠️ 这是最常见的卡点：协议没签完，内购菜单根本不会出现，或者商品保存后一直显示「等待协议」。

---

## 第 1 步：创建订阅组

进入 **我的 App → Read Me To Sleep → 订阅（Subscriptions）**

1. 点击 **创建订阅组**
2. **参考名称**：`ReadMeToSleep 会员`
3. 创建后记下这个组，稍后两个商品都放进来

> 一个订阅组内的商品，用户只能订阅其中一个，且切换时 Apple 自动处理升级/降级。我们的月/年会员正好放同一组。

---

## 第 2 步：创建「月度会员」商品

在订阅组内点击 **创建订阅**，填写：

| 字段 | 值 |
|---|---|
| 参考名称 | `月度会员` |
| **产品 ID** | `com.seal023.ReadMeToSleep.monthly` ⚠️ 一次性设定，**创建后不可修改** |
| 订阅时长 | 1 个月 |
| 价格 | 选择 **¥28.00**（中国区价格档） |

**本地化信息**（至少填简体中文）：

| 字段 | 值 |
|---|---|
| 订阅显示名称 | `月度会员` |
| 描述 | `解锁无限故事生成、声音克隆、离线下载，灵活订阅，随时取消。` |

**App Store 推广**（可选，但建议填）：
- 上传一张 1024×1024 的订阅图标（不上传也能过审）

保存。

---

## 第 3 步：创建「年度会员」商品

同上，在**同一个订阅组**内再创建一个：

| 字段 | 值 |
|---|---|
| 参考名称 | `年度会员` |
| **产品 ID** | `com.seal023.ReadMeToSleep.yearly` |
| 订阅时长 | 1 年 |
| 价格 | 选择 **¥168.00** |

**本地化信息**（简体中文）：

| 字段 | 值 |
|---|---|
| 订阅显示名称 | `年度会员` |
| 描述 | `解锁全部会员权益，约 ¥14/月，比月度订阅省 40%。` |

保存。

> 关于「省 40%」：页面里写了这个角标。¥28×12 = ¥336，¥168 ÷ ¥336 ≈ 5 折。如果 Apple 认为宣传与实际不符会追问，建议把 App 里的角标文案改成**「省 50%」**或**「立省 ¥168」**，两者都算得通。代码位置：`app/(parent)/subscription.tsx` 里的 `省 40%` 与 `约 ¥14/月，最划算`。

---

## 第 4 步：关联到待提交的版本

回到 **App Store → Read Me To Sleep → 准备提交** 的版本页面，往下滚到 **「App 内购买项目和订阅」**区块：

1. 点击该区块的 **+** 或 **添加**
2. 勾选刚才建的 `monthly` 和 `yearly` 两个商品
3. 保存

> 漏了这步，审核员在版本里看不到内购商品，会以「订阅功能不完整」拒审。

---

## 第 5 步：填订阅相关的元数据（同在版本页面）

- **订阅条款（Terms）**：如果还没有自己的 EULA，用 Apple 默认的即可
- **隐私政策链接**：必填，见「上架材料清单」
- **服务条款链接（EULA）**：订阅类 App 必填

代码里这两个链接是占位符，**上架前必须替换**：

`app/(parent)/subscription.tsx` 顶部：
```ts
const TERMS_URL = 'https://example.com/readmetosleep/terms.html';
const PRIVACY_URL = 'https://example.com/readmetosleep/privacy.html';
```

---

## 第 6 步：沙盒测试（强烈建议，别跳过）

内购不实测，上架后出问题只能靠发版修。

1. **App Store Connect → 用户和访问 → 沙盒测试员**，创建一个沙盒账号（用一个没注册过 Apple ID 的邮箱）
2. 在 iPhone 上：**设置 → App Store → 沙盒账户** 登录该账号
3. 用 **TestFlight** 或 Xcode Cloud 构建包安装 App，进入订阅页：
   - ✅ 价格应显示为商店真实价格（沙盒环境下价格会带「(Sandbox)」或显示为对应货币）
   - ✅ 点购买 → 应弹出 Apple 支付确认 → 确认后显示「订阅成功」
   - ✅ 杀掉 App 重进 → 应仍显示会员身份（校验 `refreshEntitlement` 生效）
   - ✅ 点「恢复购买」→ 应提示已恢复并带有效期
4. 沙盒环境下订阅周期会**大幅加速**（1 个月 ≈ 5 分钟），可以顺带验证过期逻辑

## 常见问题

**Q：商品显示「元数据缺失」无法提交？**
A：本地化信息里的显示名称和描述没填全。

**Q：商品状态一直是「等待审核」？**
A：正常。内购商品要随 App 版本一起过审，或者先单独提交内购审核通过后再提交 App。建议**先单独提交内购商品审核**，通过后再提 App 版本，这样 App 送审时内购已是「已批准」状态，被卡概率更低。

**Q：App 里拉不到价格？**
A：按顺序排查——
1. 产品 ID 是否与代码里**完全一致**（含大小写）
2. 沙盒/真机是否登录了可用的 Apple ID
3. 内购商品状态是否为「已批准」或至少「准备提交」（「元数据缺失」状态下拉不到）
4. 是否用的是**真机构建**（Expo Go 没有原生模块，`isIapSupported` 会返回 false）

**Q：`pod install` 报 NitroIap 相关错误？**
A：已修复——`react-native-nitro-modules` 之前漏写在 package.json 里，现已补上（commit `fed1c19`）。若仍报错，确认 Xcode Cloud 用的是最新 main 分支。
